# Accessibility (A11y)

Target: **WCAG 2.2 level AA** on all platforms, plus platform guidance (Material accessibility, Apple HIG).

## Built into the foundations
| Requirement | WCAG | How the system enforces it |
|---|---|---|
| Text contrast 4.5:1 | 1.4.3 | 76 token pairs × 2 themes checked on every build |
| Non-text contrast 3:1 (icons, control borders, focus) | 1.4.11 | Same check; `color-border-input-*`, `color-border-focus` |
| Not color alone | 1.4.1 | Status = color + icon/text (component rule) |
| Visible focus | 2.4.7, 2.4.11, 2.4.13 | 2px focus ring + 2px offset tokens; editable fields use the documented exception below |
| Target size | 2.5.8 | `target-min`: 24px web, 48dp tablet/mobile |
| Reflow / zoom | 1.4.4, 1.4.10 | Fluid grid, no fixed content widths |
| Text spacing | 1.4.12 | Line heights ≥ 1.5 for body roles; no clipped text containers |
| Motion | 2.3.3 | Reduced-motion durations |
| Language of page | 3.1.1 | `lang` set by `BiowaveProvider`; Flutter `locale` |

## Every component must
- Be fully keyboard operable (web: Tab / Shift+Tab / Enter / Space / Esc / arrows as per WAI-ARIA APG pattern).
- Expose role, name, state and value (native elements first; ARIA only when needed; Flutter `Semantics`).
- Show focus only for keyboard (`:focus-visible`).
- **Editable-field exception:** Text field, Text area and field-based controls use the input border itself as the focus indicator: `border-width-focus` in `color-border-focus`, with no exterior offset. An error field keeps `color-border-input-error` at the same focus width. This avoids a double outline around native outlined fields while retaining the required area and 3:1 non-text contrast. Other controls keep the 2px ring and 2px offset.
- Announce async results (toasts/snackbars use `role="status"` / `SemanticsService.announce`).
- Work at 200% text size and with screen readers in Arabic and English (VoiceOver, TalkBack, NVDA).
- Keep errors next to the field, in text, linked with `aria-describedby`.

## Testing checklist
- Automated: axe (web), `flutter test` with `meetsGuideline(textContrastGuideline)` and `androidTapTargetGuideline`.
- Manual: keyboard pass, screen reader pass (en + ar), dark mode pass, 200% zoom.
