# Benefits

| For | Benefit |
|---|---|
| **Employees and admins** | The same action looks and behaves the same on web, tablet and phone. Arabic and English are equal citizens, not a translated afterthought. Light and dark themes both meet WCAG 2.2 AA. |
| **Designers** | Decisions are made once (a token, a component) instead of per screen. Time goes to product problems — enrollment, approvals, device health — not to re-picking greys. |
| **Engineers** | Typed tokens for TypeScript and Dart, a ready MUI theme and Material 3 ThemeData. No hard-coded values to hunt down when the brand or a contrast rule changes. |
| **Product / business** | Faster delivery of new modules, fewer UI bugs, one place to fix accessibility and RTL issues, and a consistent brand across clients (Arana Security, TigrisNet, Biowave). |
| **AI agents** | Every section has a README that summarises it, components follow a written plan with acceptance criteria, and a reviewer checks the result against that plan. |

## Measurable signals
- Share of screens built only from system components (target ≥ 80% on new work).
- Number of raw color / px values in product code (target 0; lintable).
- Accessibility defects found in QA per release.
- Time from approved design to shipped component on all three platforms.
